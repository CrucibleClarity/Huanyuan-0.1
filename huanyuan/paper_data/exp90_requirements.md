# EXP-90: num 泛化 num 推理速度 (G5 — 直觉路径成本)

> 日期: 2026-08-11 | 状态: 需求 + 实现 | 命题: G5 (直觉 = 编译后的低成本执行)

## 目的

对比同一算术任务 (20 位加法) 的两种计算路径推理速度:
- **结构计算**: 数字逐位展开为 token 序列 (82 token), 模型逐位重建 (慢)
- **直觉计算**: 20 位数字压缩为单个 num 原子 token (num 泛化), 模型短序列快速判定

证明直觉路径 (num 泛化原子 token) 成本 < 结构路径 (逐位展开), 且语义一致。

## 关键要素 (用户要求)

1. **num 泛化出的 num**: 用 tokenizer 的 num 泛化机制 (value_token / iterate_from_base /
   arrow 链) 得到 20 位数字的原子 num token, 而非硬编码 digit 序列 — 泛化出的
   num 才是"直觉"表示。
2. **严谨对照**: 结构 vs 直觉, 同一输入同一任务, 只变表示, 记录:
   - 序列长度 (token 数)
   - 推理耗时 (per 前向)
   - 语义一致性 (两路径结果一致)
3. **算法推理速度**: 记录 token 前向成本随表示压缩度的变化。

## 实现步骤

1. 检查 tokenizer num 泛化: value_token(n) 对 n≥10 是否泛化出原子 token
   (arrow 链)。若不支持, 需确认泛化范围 (0-9 原子 + digit 序列结构)。
2. 定义 20 位数字的直觉表示: 原子 num token (若泛化支持) 或 紧凑结构。
3. 结构路径: numeral_of 逐位展开 (82 token)。
4. 直觉路径: 原子 num token (短序列)。
5. 测两路径推理耗时 + 语义一致性。

## 验收

- 直觉路径 token 数 < 结构路径 (期望 ≤1/4)
- 直觉路径耗时 < 结构路径 (期望 ≥2×)
- 两路径结果一致 (语义等价)
